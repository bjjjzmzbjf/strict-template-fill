# 严格套模板 strict-template-fill

将格式不齐的 Word 原稿统一填入同一母版的 Agent Skill。适合报名表、审批表、合同、学生材料及其他具有固定结构的批量文档。

**先保留公共部分并制作母版 → 每份独立复制母版 → 无格式填入内容 → 核对内容、全部格式和每一页版面。**

> 生成的文件需要与模板或者参考文件的格式严格一致，包括字体、段落间距、缩进、行距、表格大小、表格内排布、居中等等等所有格式完全一致。

这句话原文保留在技能入口。格式严格一致是执行与验收要求；本仓库提供工作流程，不包含适用于任意 Word 文件的一键转换程序，也不保证不同编辑器之间像素完全相同。

## 能做什么

- 从空白模板或已填写参考文件中保留公共文字、表格和全部格式，清除逐份变化的信息。
- 每份输出重新复制同一母版，只引入原稿内容，不引入原稿样式或表格结构。
- 保持字体、段落、页面、表格、图片及签名日期等对应位置的格式与布局。
- 同时检查输出与母版、各份输出的同类位置，发现溢出或不确定字段时记录异常。
- 分开完成逐字段核对、结构与格式核对、逐份逐页视觉核对。

## 使用条件

需要支持本地技能文件、文档读写的代理环境，以及用户提供的 `.docx` 模板或参考文件、原稿与输出目录。只有实际执行了渲染并查看所有页面，才能确认视觉验收通过。

文档工具按实际环境选择，例如 Python/OOXML、Open XML SDK、Word 或 LibreOffice 渲染。Python、Node.js 和 .NET 不要求全部安装；本技能本身不捆绑这些程序，也不要求特定私有插件。运行文档任务时先检查所选工具、字体与格式支持。旧版 `.doc` 需先另存为 `.docx`，并检查转换造成的差异。

## 安装

将本仓库下载或克隆后，把包含 `SKILL.md`、`agents/`、`references/` 的目录安装为 `strict-template-fill`，放入代理支持的技能目录。保留文件之间的相对路径，不只复制 `SKILL.md`。

例如，Codex 环境可使用其配置的技能目录；本机目录位置应由实际配置决定，不要照搬其他电脑的绝对路径。

若使用 Skills CLI，可按其支持的方式安装：

```bash
npx skills add bjjjzmzbjf/strict-template-fill --skill strict-template-fill
```

CLI 并非本技能依赖；本仓库的发布检查不等于已在所有代理或安装器中完成兼容性测试。

## 使用示例

```text
请使用 $strict-template-fill，将“原稿”文件夹中的全部 Word 文件，
按“参考表单.docx”严格统一格式。

先从参考文件中只保留公共部分及完整格式，制作统一母版；
每份原稿都独立复制母版，再无格式填入内容。
只统一格式，不修改文字和数据，不擅自缩字、改表格或移动签名。
保留原稿，输出放入“统一格式结果”，沿用原文件名。
逐字段核对内容，逐份查看每一页，并列出缺失信息和容量冲突。
```

只需要指定模板、原稿位置和修改范围。明确的任务无需额外增加批准母版、批准样本等环节；公共内容或字段对应关系确有歧义时再澄清。

## 验收与限制

内容、格式、视觉检查各自记录“通过／未通过／未执行”，任何一项未确认都不能写成全部通过。对每一份文件逐字段、逐页验收，批量任务不能只抽查首份或首尾页。格式相同不意味着不同文字占用相同行数；文字超出固定区域时报告冲突，不调整母版来掩盖问题。

公式、上下标、域、文本框、控件或图片等不能简单当作纯文本丢弃。工具无法可靠处理时应明确说明范围。模板原有缺陷与本次引入的问题分别记录。

本仓库的 Markdown/YAML 检查只能确认技能包结构；[验收场景](references/验收场景.md)是未来文档任务的检查用例，不代表已经执行这些 Word 转换测试。

## 反馈与贡献

提交 Issue 时说明文档类型、编辑器和字体环境、触发步骤、预期与实际差异，以及是否能复现。优先提供最小的虚构或脱敏样例，不上传真实姓名、编号、电话、签名、合同或其他未获许可的材料。

修改流程时保留入口中的严格格式原句，检查相对链接及 YAML，并按验收场景审阅规则。若执行了实际文档测试，请说明所用样例、工具版本及完成范围，不将抽查写成全面通过。
