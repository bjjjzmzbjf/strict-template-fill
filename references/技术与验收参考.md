# 技术与验收参考

## 编辑方式

优先定位母版已有的内容控件、书签、占位符或 XML 文本槽位，仅替换可变内容。每份从同一母版副本开始；不导入原稿样式、段落属性或表格结构。原稿中的公式、图片、链接等语义对象单独处理，不能因无格式填入而丢失含义。

在 OOXML 中，文本通常位于 `w:t`，字符格式位于 `w:rPr`，段落格式位于 `w:pPr`。样式、主题和默认值也会影响实际显示，不能只比较一个字体字段或样式编号。跨多个 run 的槽位按边界处理，保留不同格式段；重建目标 run 时仅使用母版相应格式。

文本必须正确转义，并保留空格、制表位与显式换行的语义。使用解析器和精确节点定位，避免整文件字符串替换造成跨字段误改。添加图片、链接等时核对包关系与目标引用，不能只替换可见文字。

## 常见接口陷阱

- 给 `python-docx` 的 `Paragraph.text` 赋值会替换原内容并丢失 run 层格式；`Paragraph.clear()` 清除的字符格式也不能自动恢复。不要清空模板后用默认 run 重写。[官方接口文档](https://python-docx.readthedocs.io/en/latest/api/text.html#docx.text.paragraph.Paragraph.text)
- `docxtpl` 普通字符串变量保留当前位置样式；`RichText` 及 `{{r ...}}` 可以替换字符样式。段落、行、列控制标签还会删除其所在节点。严格模式应避开不必要的富文本、原稿子文档和结构循环；多行变量中的段落或分页控制字符需符合槽位规则。[官方文档](https://docxtpl.readthedocs.io/en/latest/)
- 表格首选宽度、实际渲染宽度、固定行高和最小行高不是同一概念。保留母版属性之后仍需检查实际尺寸、内容裁切和固定位置。[WordprocessingML 表格说明](https://learn.microsoft.com/en-us/office/open-xml/word/working-with-wordprocessingml-tables)
- 文件可打开或 schema 校验通过，不能证明内容正确、全部格式相同或视觉版面合格。[Open XML 结构验证说明](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-validate-a-word-processing-document)

## 工具选择

以下是可组合的实现工具，不是自动满足全部验收要求的替代流程。按任务及环境选择，避免为简单填表引入整套不必要的运行时。

| 工具 | 适用方式 | 严格模式注意事项 |
| --- | --- | --- |
| [python-docx-template](https://github.com/elapouya/python-docx-template) | Python/Jinja2 占位符填充 | 先验证标签与原格式相容，不引入原稿样式或子文档 |
| [Docxtemplater](https://github.com/open-xml-templating/docxtemplater) | JavaScript 占位符填充 | 禁止未经授权的结构循环和动态样式；部分模块单独许可或收费 |
| [Open XML SDK](https://github.com/dotnet/Open-XML-SDK) | .NET 精确包操作与结构校验 | 结构校验不能替代实际排版检查 |

这些链接用于技术参考；使用或分发工具前核对相应版本的许可。仓库不包含这些工具的源码或第三方技能全文，链接存在也不表示已在当前环境安装或运行。

## 渲染与比较

母版和输出使用同一渲染器、相同字体与缩放条件。逐份渲染并实际查看所有页面；使用 Word、LibreOffice 或环境提供的可用渲染器，记录版本及字体缺失情况。无法验证的编辑器特性明确列为限制，不声称跨编辑器完全一致。

内容变化区域不能以整页像素相等作为验收条件。固定栏目、表格外框、签名日期位置应有针对性的对齐检查；文字区域同时检查格式属性、换行、容量、遮挡和裁切。内容核对、结构格式核对与视觉核对必须分别记录。

详细记录使用 [验收记录](验收记录.md)，典型失败情况见 [验收场景](验收场景.md)。
